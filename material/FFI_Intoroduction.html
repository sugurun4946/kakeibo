Flutter × C++ FFI 完全攻略ガイド

本書は、Flutter（Dart言語）からC++のネイティブコードを呼び出す仕組み「FFI」について、その概要から内部の動作原理、メモリ管理までを初心者向けに解説したマスター資料です。

1. FFIの概要：そもそもFFIとは？

FFI（Foreign Function Interface：外部関数インターフェース）とは、あるプログラミング言語から「別の言語で書かれた関数」を直接呼び出すための架け橋（翻訳機）です。

通常、DartとC++は文法やデータの持ち方が全く異なるため直接会話できません。しかし、多くの言語は「C言語のルールに合わせる」という共通の約束事を持っています。FFIは、この「C言語の標準的な枠組み」を仲介役にすることで、国境を越えたデータのやり取りを可能にしています。

【図解：FFIの構造イメージ】
Dart (Flutter)
UI・画面制御
⇄
dart:ffi
（共通の架け橋）
⇄
C++
ロジック・SQLite

2. どんな場面で使うの？（使う理由）

  • 既存のC++コード（資産）を再利用したいとき： すでにC++で完成している家計簿ロジックやDB処理を、Flutterでわざわざ1から書き直す必要がなくなります。
  • 圧倒的な計算スピードが欲しいとき： 画像・動画編集、ゲームの物理計算、AIの暗号処理など、スマホやPCの限界まで速度を引き出したい場合に使用します。
  • OSの深い機能を直接触りたいとき： 各種ハードウェアを叩くC言語ベースのドライバーやシステムライブラリにアクセスできます。

4. アプリがC++を呼び出す動作原理

裏側では、CMakeというビルドツールを使ってC++をコンピュータが直接読める「共有ライブラリ」というファイルの塊に事前に変換しています。

Windows native_expense.dll というファイルが生成されます。
Linux libnative_expense.so というファイルが生成されます。

アプリが実行されると、Dart側は以下の4ステップでC++を呼び出します。

  1. ロード： ffi.DynamicLibrary.open() でライブラリ（.so や .dll）をメモリ上に読み込む。
  2. 検索（ルックアップ）： 塊の中から c_get_amount_including_tax という関数がメモリのどこにあるか（住所）を特定する。
  3. バインド： 見つかったC++の関数を、Dartの関数としていつでも使えるように紐付ける。
  4. 実行： Dartから引数を渡して実行し、C++からの計算結果を受け取る。

5. メモリ・スタック・ヒープの動き（ディープな裏側）

FFIを扱う上で最も重要、かつバグを出しやすいのがパソコンのメモリ管理です。メモリ空間には「スタック」と「ヒープ」という性質の異なる2つの領域があります。

① スタック領域（一時的な作業机）

渡すデータ： 金額、税率、フラグなどの単純な数値（int, double）

動き： Dartが「1000」という数値を机に置くと、C++がそれを読み取って「1100」と書き換えて返します。関数が終わると自動で綺麗に片付くため、絶対に安全でバグが起きません。

② ヒープ領域（広大な自由倉庫）

渡すデータ： 品目名、日付などの「文字列（String）」や「構造体配列」

動き： データサイズが大きいため作業机には載りません。Dartが倉庫（ヒープ）にデータを配置し、C++には「倉庫のB棟5番棚にあります」という『ポインタ（住所）』だけを教えます。

⚠️ 今後（Day 6以降）の注意点：ポインタの罠
Dartには「不要なメモリを自動で片付ける仕組み(GC)」がありますが、C++側はそれを知りません。DartがC++に住所を教えた直後、勝手に倉庫の中身を片付けてしまう（更地にする）ことがあります。その状態でC++がその住所を覗きに行くと、「データが存在しない！」となってアプリが跡形もなくクラッシュします。
そのため、文字列をやり取りするときは、明示的に「C++が終わるまで片付けないで！」というメモリ固定と、処理が終わった後の手動での解放処理が必要になります。
